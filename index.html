Transformer Visual Lab

One bench per concept, each in four parts: the math (typeset, with every symbol explained), try it (change the inputs), your numbers, step by step (the formula redone live with what you entered), and the exam trap. Every bench opens on a past-paper or assignment example, so the numbers match the answer keys.

Symbols used on this page

T: tokens in the sequence (context length)
d_{model}: width of every token vector
h: attention heads, with d_k=d_v=d_{model}/h
d_{ff}: hidden width of the feed-forward net
B: batch size; N: layers per stack
|V|: vocabulary size
H,\ Q,\ K,\ V: inputs, queries, keys, values, one row per token
A\in\mathbb{R}^{T\times T}: attention weights; Z=AV
M: mask added before the softmax, entries 0 or -\infty

Convention: row vectors, as in the course notes. The MultiHeadAttention deck writes the transposed (column) form; Lab 3 shows both side by side.

Lab 1

Self-attention by hand

L3Note 01 §3–5, Example 1Past papers H: GA1 Q3 · 2025T2-Q12–14 · 2026T2-Q2–3

Every token asks a question (its query), compares it with every token's key, turns the scores into weights with a softmax, and takes the weighted sum of the values. Row i of the weight matrix is token i's attention, so each row must sum to 1.

The math

Q = HW_Q,\qquad K = HW_K,\qquad V = HW_V
A=\operatorname{softmax}_{\text{row}}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right),\qquad Z = AV
e_{ij}=\frac{q_i\cdot k_j}{\sqrt{d_k}},\qquad \alpha_{ij}=\frac{\exp(e_{ij})}{\sum_{l=1}^{T}\exp(e_{il})},\qquad z_i=\sum_{j=1}^{T}\alpha_{ij}\,v_j
  • H\in\mathbb{R}^{T\times d_{model}} has one row per token.
  • W_Q, W_K, W_V\in\mathbb{R}^{d_{model}\times d_k}, so Q, K, V\in\mathbb{R}^{T\times d_k}.
  • e_{ij} is how well query i matches key j. Row i of A turns those scores into weights that sum to 1.
  • z_i is a weighted average of the value vectors, so Z\in\mathbb{R}^{T\times d_v}.

Why divide by \sqrt{d_k}? If the entries of q_i and k_j are independent with mean 0 and variance 1, then \operatorname{Var}(q_i\cdot k_j)=d_k. Large scores push the softmax towards a one-hot vector whose gradients are almost zero. Dividing by \sqrt{d_k} brings the variance back to 1.

Try it

Exam trap. The softmax runs along each row (over keys). GA questions often say "ignore the scaling": read for it. If your row-wise answer isn't among the options, the key may have used columns, as GA1 Q3 and 2025T2-Q13–15 did.

Lab 2

Attention counts and the causal mask

L6 · L9Note 02 §3Past papers G: 2025T3-Q14, Q15, Q17, Q18 · 2026T2-Q4, Q6

Each head scores every query against every key: T × T numbers. The decoder's causal mask sets everything above the diagonal to −∞, so token i only sees tokens 1…i. Most counting questions are one of the formulas on the right.

The math

M_{ij}=\begin{cases}0 & j\le i\\ -\infty & j>i\end{cases}\qquad A=\operatorname{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}+M\right),\qquad e^{-\infty}=0
\text{kept}=\sum_{i=1}^{T} i=\frac{T(T+1)}{2},\qquad \text{masked}=T^2-\frac{T(T+1)}{2}=\frac{T(T-1)}{2}
\text{scores in a batch}=B\cdot h\cdot T^2,\qquad \text{next-token targets}=B\,(T-1)
  • Query i may look at keys 1,\dots,i: that is i cells in row i. Adding the rows gives the triangle number.
  • Adding -\infty before the softmax makes those weights exactly 0, so the future never leaks in.
  • Every head scores its own T\times T grid, and every sequence in the batch has its own heads.
  • With no BOS token, the last token has nothing after it to predict: T-1 targets per sequence.

Try it

Exam trap. "Non-zero scores" means the kept cells, T(T+1)/2, including the diagonal. "Masked entries" is T(T-1)/2. Batch size and the number of heads are often distractors when the question says "per head, one sequence".

Lab 3

Multi-head attention

L4Note 01 §6, Examples 3–4Past papers A H: GA1 Q1 · 2025T1-Q10–11 · 2025T3-Q16, Q19 · 2025T2-Q13–15

The model width dmodel is cut into h slices of dk = dmodel/h. Each head runs its own attention in its slice, the outputs are concatenated back to dmodel, and WO mixes them. The parameter count does not depend on h.

The math

d_k=d_v=\frac{d_{model}}{h},\qquad \text{head}_i=\operatorname{softmax}\!\left(\frac{Q_iK_i^{\top}}{\sqrt{d_k}}\right)V_i\in\mathbb{R}^{T\times d_v}
\operatorname{MHA}(H)=\big[\,\text{head}_1\;\big|\;\cdots\;\big|\;\text{head}_h\,\big]\,W_O,\qquad W_O\in\mathbb{R}^{h d_v\times d_{model}}
\#\text{params}=\underbrace{h\cdot 3\,d_{model}\,d_k}_{W_Q,\,W_K,\,W_V}+\underbrace{h\,d_v\,d_{model}}_{W_O}=3d_{model}^2+d_{model}^2=4d_{model}^2
  • Each head has its own W_Q^{i}, W_K^{i}, W_V^{i}\in\mathbb{R}^{d_{model}\times d_k}, so it can attend to a different relation, such as syntax in one head and who-refers-to-whom in another.
  • The concatenation is T\times h d_v = T\times d_{model}, and W_O mixes the heads back together.
  • Doubling h halves d_k. The cost and the parameter count stay the same; only the number of attention patterns grows.

Try it

Exam trap. Check whether the question includes W_O (2025T1-Q10 excludes it: 3d_{model}^2). The course counts no attention biases. One head's W_Q is d_{model}\times d_k, not d_{model}\times d_{model}.

Lab 4

BatchNorm vs LayerNorm

L8 · L10Note 02 §10, Example 4bPast papers B: 2024T3-Q8–11 · 2025T1-Q12–15 · 2025T2-Q17–18 · 2025T3-Q7

Same matrix, different axis. BatchNorm normalises each feature across the samples in the batch. LayerNorm normalises each sample across its own features. Read the question's orientation sentence first, then pick the axis.

The math

\textbf{BN}\ (\text{feature } j \text{ over } m \text{ samples}):\quad \mu_j=\frac1m\sum_{i=1}^{m}x_{ij},\qquad \sigma_j^2=\frac1m\sum_{i=1}^{m}\big(x_{ij}-\mu_j\big)^2
\textbf{LN}\ (\text{sample } i \text{ over } H \text{ features}):\quad \mu_i=\frac1H\sum_{j=1}^{H}x_{ij},\qquad \sigma_i^2=\frac1H\sum_{j=1}^{H}\big(x_{ij}-\mu_i\big)^2
\hat x=\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}},\qquad y=\gamma\,\hat x+\beta,\qquad \gamma,\beta\in\mathbb{R}^{H}\ \Rightarrow\ 2H \text{ learnable parameters}
\sum_{k=1}^{n}\frac{x_k-\mu}{\sigma}=\frac{\left(\sum_k x_k\right)-n\mu}{\sigma}=\frac{n\mu-n\mu}{\sigma}=0
  • Here x_{ij} is sample i, feature j. Which way that runs on the page depends on the question's orientation sentence.
  • BN depends on the batch: with batch size 1 every \sigma_j=0. LN uses one sample's own features, which is why transformers use LN.
  • The last line is why "the sum of a normalised row (BN) or column (LN)" is always 0.

Try it

Exam trap. The axis. Find "each column represents a sample" or "rows represent samples" first. σ uses 1/m, not 1/(m-1). Two past keys got this wrong (2025T1-Q14/Q15 swapped; 2024T3-Q10/Q11 computed for a different matrix).

Lab 5

Sinusoidal positional encoding

L5 · L7Note 02 §7–8, Example 3Past papers F: GA3 Q1 · 2024T3-Q20 · 2025T2-Q10 · 2026T1-Q11 · 2026T2-Q7

Each pair of dimensions (2i, 2i+1) is a sine and cosine at its own frequency 1/100002i/d. Early dimensions oscillate fast, late ones barely move, so every position gets a unique pattern. Nothing here is learned.

The math

PE_{(pos,\,2i)}=\sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right),\qquad PE_{(pos,\,2i+1)}=\cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right)
\omega_i=10000^{-2i/d_{model}}:\qquad \omega_0=1\ \ (\text{period }2\pi\approx6.3\text{ positions})\ \ \longrightarrow\ \ \omega_{d/2-1}\approx10^{-4}\ \ (\text{period}\approx 63{,}000)
\lVert PE_{pos}\rVert^2=\sum_{i=0}^{d/2-1}\big(\sin^2\theta_i+\cos^2\theta_i\big)=\frac{d_{model}}{2}\quad\text{for every }pos
\begin{bmatrix}\sin\omega(p+k)\\ \cos\omega(p+k)\end{bmatrix}=\begin{bmatrix}\cos\omega k & \sin\omega k\\ -\sin\omega k & \cos\omega k\end{bmatrix}\begin{bmatrix}\sin\omega p\\ \cos\omega p\end{bmatrix}
  • Element j belongs to pair i=\lfloor j/2\rfloor. Even j uses sin, odd j uses cos, and both use the same angle \theta_i=pos\cdot\omega_i.
  • PE is added to the word embedding (x+PE), so it has the same width d_{model}. The whole table is T\times d_{model}, with 0 parameters.
  • The rotation identity (beyond slides): moving k positions rotates each (sin, cos) pair by a fixed angle that doesn't depend on p. That is how relative offsets become visible to attention.

Try it

Exam trap. Use radians. Use the position exactly as given. For element j, the exponent uses 2i=2\lfloor j/2\rfloor, not j (2026T1-Q11: element 5 → \cos(3/10000^{4/128})). Sinusoidal PE has 0 learnable parameters.

Lab 6

Decoding explorer: greedy, beam, exhaustive

L17 · L19 · L20Note 04 §3–7, WE2Past papers D: 2025T1-Q7–8 · 2025T2-Q19–20 · 2025T3-Q6, Q8, Q9 · 2026T2-Q14, Q16

A toy model with three tokens and three steps. Greedy keeps one path and can miss the best sequence. Beam search keeps the k best partial sequences by joint probability. Exhaustive search scores all |V|L sequences.

The math

P(w_{1:L})=\prod_{t=1}^{L}P(w_t\mid w_{<t}),\qquad \log P(w_{1:L})=\sum_{t=1}^{L}\log P(w_t\mid w_{<t})
\text{greedy: } w_t=\arg\max_{w}P(w\mid w_{<t}),\qquad \text{beam }k\text{: keep the }k\text{ prefixes with the largest }\prod_{s\le t}P(w_s\mid w_{<s})
\#\text{sequences of length }L=|V|^{L},\qquad \#\text{exhaustive decoder runs}=\sum_{t=1}^{L}|V|^{t-1}=\frac{|V|^{L}-1}{|V|-1}
  • At step t, exhaustive search runs the decoder once for each of the |V|^{t-1} prefixes. Greedy runs once; beam runs k times and scores k\,|V| candidates.
  • Greedy commits early: a slightly less likely first word can lead to a much more likely sentence. Beam search hedges by keeping k candidates.
  • Length normalisation, \tfrac{1}{L}\sum_t\log P, stops beam search preferring short outputs.

Try it

Exam trap. Decoder runs at step t are |V|^{t-1}, not |V|^{t}. The total for L steps is the sum (2026T2-Q14: 1+7+49+343=400). Paths kept at step t are 1 (greedy), k (beam) and |V|^t (exhaustive).

Lab 7

Sampling: top-k, top-p, temperature

L18 · L22Note 04 §9–11Past papers E: GA4 Q1d · 2025T2-Q4, Q9, Q11, Q21 · 2025T3-Q10 · 2026T1-Q6 · 2026T2-Q15

Temperature reshapes the distribution without changing the ranking. Top-k keeps the k most likely tokens; top-p keeps the smallest set whose probability reaches p. Both then renormalise and sample, which is why they are the only non-deterministic strategies.

The math

\text{top-}k:\quad \tilde P(w)=\begin{cases}\dfrac{P(w)}{\sum_{w'\in V^{(k)}}P(w')} & w\in V^{(k)}\\[6pt] 0 & \text{otherwise}\end{cases}
\text{top-}p:\quad V^{(p)}=\text{the smallest set of most-likely tokens with }\sum_{w\in V^{(p)}}P(w)\ \ge\ p,\ \text{then renormalise as above}
\text{temperature}:\quad P_T(w_i)=\frac{e^{u_i/T}}{\sum_j e^{u_j/T}}=\frac{p_i^{1/T}}{\sum_j p_j^{1/T}},\qquad T\to0:\ \text{argmax},\qquad T\to\infty:\ \text{uniform}
  • u_i are logits and p_i the probabilities at T=1. Both forms of the temperature formula give the same distribution.
  • Dividing logits by T keeps their order, so temperature changes how peaked the distribution is, never which token is most likely.
  • Top-k with k=1 is greedy. Top-p adapts: a peaked distribution keeps few tokens, a flat one keeps many.

Try it

Exam trap. Renormalise: divide by the kept mass, not by 1 (GA4 Q1d: 0.41/0.64=0.6406). Only the sampling methods are non-deterministic; greedy, beam and exhaustive always give the same output.

Lab 8

Teacher forcing vs inference

L9Note 02 §2Past papers I: 2024T3-Q2 · 2025T1-Q3 · 2025T3-Q3, Q5 · 2026T2-Q8

In training, the decoder is fed the true previous token at every step (the target shifted right), so all positions run in one masked pass. At inference there is no target: the model feeds back its own predictions, one pass per token, and an early mistake carries forward.

The math

\text{training: }\ \mathcal{L}=-\sum_{t=1}^{T}\log P\big(y_t\mid \underbrace{y_1,\dots,y_{t-1}}_{\text{true tokens}},\,x\big)\qquad\text{(all positions in one masked pass)}
\text{inference: }\ \hat y_t=\arg\max_{w}P\big(w\mid \underbrace{\hat y_1,\dots,\hat y_{t-1}}_{\text{its own predictions}},\,x\big)\qquad\text{(one pass per generated token)}
  • Decoder input in training = target shifted right: \langle\text{go}\rangle, y_1, \dots, y_{T-1}. The causal mask stops position t from seeing y_t.
  • Without teacher forcing, one early mistake would feed every later step, making training slow and unstable.
  • The gap between training on true prefixes and generating from its own is called exposure bias.

Try it

Exam trap. Under teacher forcing, the input at step t is the true y_{t-1}, whatever the model predicted before (2025T3-Q3). Training needs 1 decoder pass; inference needs one per output token, plus one for the end token if it must be generated.

Lab 9

Encoder–decoder: data flow and parameters

L2 · L6 · L8 · L10Note 02 §11–12, Example 5Past papers A: GA2 Q1 · 2024T3-Q4–6 · 2025T1-Q9

The encoder layer is attention, then a feed-forward net, each wrapped in Add & Norm. The decoder layer adds a second attention block whose queries come from the decoder and whose keys and values come from the encoder output. That is why a decoder layer has 2 attention blocks and 3 LayerNorms.

The math

\text{MHA}=3h\,d_{model}\,d_k+h\,d_v\,d_{model}\ \big(=4d_{model}^2\big),\qquad \text{FFN}=2\,d_{model}\,d_{ff}\ \big(+\,d_{ff}+d_{model}\text{ with biases}\big),\qquad \text{LN}=2\,d_{model}
\text{encoder layer}=\text{MHA}+\text{FFN}+2\,\text{LN},\qquad \text{decoder layer}=\underbrace{2\,\text{MHA}}_{\text{masked + cross}}+\text{FFN}+3\,\text{LN}
\text{embedding}=|V|\,d_{model},\qquad \text{output layer}=d_{model}\,|V_{tgt}|,\qquad \text{sinusoidal PE}=0
  • Add & Norm is \operatorname{LN}\big(x+\text{Sublayer}(x)\big). The residual add has no parameters; each LN has \gamma,\beta\in\mathbb{R}^{d_{model}}.
  • Cross-attention has the same weight shapes as self-attention. Only the source of K and V changes (the encoder output).
  • The FFN acts on each position separately: \max(0,\,xW_1+b_1)\,W_2+b_2 with W_1\in\mathbb{R}^{d_{model}\times d_{ff}}.

Try it

Exam trap. A decoder layer has 2 attention blocks and 3 LayerNorms. Check whether biases count, and whether the question wants embeddings and the output layer included (GA2 asks for them separately).

Lab 10

Seq2seq (Bahdanau) attention

L1 · L2Note 01 §1Past papers H: 2026T1-Q12–14 · 2026T2-Q1 · 2025T1-Q5

Before transformers, an RNN decoder at step t scored every encoder state hj against its own state st−1, turned the scores into weights α with a softmax, and used the weighted sum of encoder states as its context vector. Self-attention keeps the idea and swaps the scoring network for a dot product.

The math

e_{tj}=V_a^{\top}\tanh\!\big(U_{att}\,s_{t-1}+W_{att}\,h_j\big),\qquad \alpha_{tj}=\frac{\exp(e_{tj})}{\sum_{l=1}^{T_s}\exp(e_{tl})},\qquad c_t=\sum_{j=1}^{T_s}\alpha_{tj}\,h_j
  • s_{t-1} is the decoder's state before emitting word t; h_j is the encoder state of source word j.
  • \alpha_t is a distribution over the source words (it sums to 1). c_t is a fresh context vector for every target word, instead of one fixed vector for the whole sentence.
  • Self-attention keeps the recipe but scores with a dot product of learned projections, e_{ij}=q_i\cdot k_j/\sqrt{d_k}, and drops the recurrence.

Try it

Exam trap. The softmax denominator includes all encoder states. The context vector is a weighted sum of encoder states, not decoder states (2026T2-Q1).

See also Visualizing a neural machine translation model

Lab 11

Sequence probability from a model's table

L11 · L14 · L20Note 03 §2–3 · Note 04 §1, WE1Past papers C: GA4 Q1 · 2024T3-Q12–14 · 2026T2-Q9–11, Q13

A language model gives P(next token | tokens so far). The probability of a sentence is the product of those conditionals. A table like this is computed along one particular prefix, so the moment your sentence leaves that prefix, the later rows no longer apply.

The math

P(x_1,\dots,x_L)=P(x_1)\,P(x_2\mid x_1)\cdots P(x_L\mid x_1,\dots,x_{L-1})=\prod_{t=1}^{L}P(x_t\mid x_{<t})
\text{row } t \text{ of the table}=P\big(\,\cdot\mid \text{the prefix it was computed on}\big)
  • The chain rule is exact. A language model learns each conditional factor, and the sentence probability is their product.
  • A decoding table is computed along one prefix (here the greedy one). Once your sentence differs from that prefix, later rows are conditionals of a different sentence.
  • Logs turn the product into a sum, which is what beam search and the training loss use.

Try it

Exam trap. The −1 (insufficient information) answer. Before multiplying, check that every factor you need is a conditional on your prefix (2024T3-Q14, 2026T2-Q11).

Lab 12

Who can see whom: the three attention masks

L6 · L13Note 02 §3–4 · Note 03 §4Past papers I: 2026T1-Q4, Q10 · 2025T3-Q4, Q12

Encoder self-attention lets every token see every token. Decoder self-attention is causal. Cross-attention lets each target position see the whole source, so it needs no causal mask, only a padding mask for empty source slots.

The math

M^{enc}_{ij}=0,\qquad M^{dec}_{ij}=\begin{cases}0 & j\le i\\ -\infty & j>i\end{cases},\qquad M^{cross}_{ij}=0\quad(\text{only [PAD] columns get }-\infty)
Q_{dec}\in\mathbb{R}^{T_t\times d_k},\quad K_{enc},V_{enc}\in\mathbb{R}^{T_s\times d_k}\ \Rightarrow\ Q_{dec}K_{enc}^{\top}\in\mathbb{R}^{T_t\times T_s},\quad \text{output}\in\mathbb{R}^{T_t\times d_v}
  • The encoder reads a sentence that already exists, so every token may look at every other token.
  • The decoder writes left to right, so position i must not see target words after it.
  • Cross-attention looks at the source, which is fully known, so there is nothing to hide except padding.

Try it

Exam trap. "Is causal masking applied in cross-attention?" No; only a padding mask (2026T1-Q4 → c). The cross-attention score matrix is T_t\times T_s, not square.

Lab 13

GPT: pre-training to fine-tuning

L12 · L14 · L15 · L16Note 03 §5–11Past papers A I: GA3 Q3–Q5 · 2024T3-Q16–18 · 2025T1-Q6 · 2025T3-Q17 · 2026T1-Q15–19 · 2026T2-Q12

Pre-training: predict every next token of unlabelled text with a causal mask, all parameters starting random. Fine-tuning: start from those weights, wrap the input in special tokens, and train a small head on labelled data.

The math

\mathcal{L}_{CLM}(\theta)=-\sum_{i=1}^{T-1}\log P_\theta\big(x_{i+1}\mid x_1,\dots,x_i\big)\qquad(\text{every position, one masked pass, no labels})
\text{fine-tune: }\ \hat y=\operatorname{softmax}\!\big(W_y\,h^{(L)}_{\langle e\rangle}\big),\qquad \mathcal{L}=-\log \hat y_{\,\text{label}}\qquad(\text{labelled data})
\#\text{params}_{\text{GPT-1}}=\underbrace{|V|\,d}_{\text{tokens}}+\underbrace{T\,d}_{\text{positions}}+N\big(\underbrace{4d^2}_{\text{attention}}+\underbrace{2d\,d_{ff}+d_{ff}+d}_{\text{FFN}}\big)
  • GPT is the transformer decoder without cross-attention: masked self-attention, FFN, LayerNorm and residuals, stacked N=12 times with d=768 and 12 heads.
  • Pre-training starts from random weights. Fine-tuning starts from the pre-trained weights and adds only W_y.
  • The output layer reuses the token-embedding matrix (tied weights), so it adds no parameters. A rare word missing from a batch can still be updated through the softmax.

Try it

Exam trap. Right-to-left languages need no mask flip: the model only sees a sequence (GA3 Q2). Shapes in GA3 Q5: PE is T\times d, one W_Q^{i} is d\times d/h, and the mask is T\times T.

Lab 14

BERT masked language modelling: 15% and 80/10/10

L21Note 05 §2–5, WE1–WE2Assignments: GA4 Q2 · past papers J: 2025T2-Q3

BERT picks 15% of positions. Of those, 80% become [MASK], 10% become a random word and 10% stay unchanged, so the model can't rely on seeing [MASK]. The loss is computed only at the picked positions, all of them.

The math

\mathcal{L}_{MLM}=-\frac{1}{|\mathcal{M}|}\sum_{i\in\mathcal{M}}\log P_\theta\big(x_i\mid\tilde x\big),\qquad \mathcal{M}=\text{the picked }15\%\text{ of positions}
\Pr[\texttt{[MASK]}]=0.15\times0.8=0.12,\qquad \Pr[\text{random word}]=\Pr[\text{unchanged}]=0.15\times0.1=0.015
  • \tilde x is the corrupted input. The model sees both sides of position i and must rebuild the original word.
  • Random and unchanged positions are still in \mathcal{M}, so the model can't learn "only [MASK] needs fixing", and [MASK] never appears at fine-tuning time anyway.
  • Unpicked positions contribute nothing to the loss, which is why BERT learns from only 15% of tokens per pass.

Try it

Exam trap. The loss uses the picked positions only. Check whether the question wants the mean (1.72) or the sum (3.44): GA4 Q2 accepted both. Use the natural log.

Lab 15

BERT input, NSP, fine-tuning and QA

L23 · L24 · L25Note 05 §6–12Past papers J: 2025T2-Q8 · 2026T1-Q5, Q7 · GA4 Q3

Each input vector is the sum of three learned embeddings: token, segment (A or B) and position. The final [CLS] vector drives next-sentence prediction and sentence classification; every token's vector drives tagging; question answering learns a start vector and an end vector.

The math

x_t=E_{\text{tok}}(w_t)+E_{\text{seg}}(A\text{ or }B)+E_{\text{pos}}(t),\qquad x_t\in\mathbb{R}^{768}
\text{NSP / classification: }\ \hat y=\operatorname{softmax}\!\big(W\,h_{[\text{CLS}]}\big)
s_i=\frac{e^{S\cdot h_i}}{\sum_{j}e^{S\cdot h_j}},\qquad e_i=\frac{e^{E\cdot h_i}}{\sum_{j}e^{E\cdot h_j}},\qquad \text{answer}=\Big[\arg\max_i s_i,\ \arg\max_j e_j\Big]\ \text{if } j\ge i,\ \text{else the empty string}
\#\text{params}_{\text{BERT-base}}=\big(|V|+2+512\big)\,d+N\big(4d^2+2d\,d_{ff}+d_{ff}+d\big)
  • All three embeddings are learned tables. The segment table has 2 rows (E_A, E_B) and the position table 512.
  • S, E\in\mathbb{R}^{768} are the only new QA parameters. The softmaxes run over paragraph positions only.
  • Fine-tuning trains all of BERT plus the small head. Feature extraction freezes BERT and trains only the head.

Try it

Exam trap. The segment embedding is never switched off: a single sentence uses E_A everywhere (2026T1-Q5). Classification uses the [CLS] vector (2026T1-Q7, GA4 Q3).

Lab 16

BERT vs GPT at a glance

L13 · L21Note 05 §1, §13 · Note 03 §4Past papers J: 2025T2-Q3

Same transformer blocks, different mask and objective. BERT's encoder sees both sides of every token and fills in blanks; GPT's decoder sees only the left side and predicts the next token, which is what makes it a generator.

The math

\text{BERT: }\ P\big(x_i\mid x_1,\dots,x_{i-1},\,x_{i+1},\dots,x_T\big)\ \ \text{for } i\in\mathcal{M}\qquad\qquad \text{GPT: }\ P\big(x_i\mid x_1,\dots,x_{i-1}\big)\ \ \text{for every } i
  • BERT conditions on both sides, which is great for understanding a sentence but gives no left-to-right way to generate one.
  • GPT conditions on the left only, so sampling one token at a time is natural.
  • Both are stacks of the same block; only the mask, the objective and the special tokens differ.

Try it

Exam trap. "The main difference between GPT and BERT pre-training" is the objective: CLM (next token) vs MLM + NSP (2025T2-Q3).
